# Scenarios

Paper exercises per skill, built from real sessions. A scenario is evidence for a change only when it tells the versions apart: run it against the skill before the change and after, and write both outcomes under Results as "met expected" or "missed expected". A case the old text already handles proves nothing about the new one; rewrite it or drop it. The one exception is a regression guard: a case where the new text must leave something unchanged, so it can only fail by acting too often; it stays when its Results line calls it a regression guard. A setup that starts after the new behaviour has happened ("the challenge ran") passes on the old text too: start it where the user types the command. A test seam that names several catches gets one case per catch. Each Results line names the commit whose skill text the run read. A later edit to that skill text, such as a review fix, makes the after-outcome stale: run the affected cases again on the final commit before the PR.
